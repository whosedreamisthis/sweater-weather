- **Weather API Layer:** Added typed Open-Meteo clients and TanStack Query hooks with no UI. `src/api/types.ts` holds `Units`, `Location`, `CurrentWeather`, `HourlyPoint`, `DailyPoint` and `Forecast`; `Forecast.location` is a `ForecastLocation` (latitude, longitude, timezone) because the forecast endpoint returns no name or id. `src/api/http.ts` provides `ApiError` (numeric `status`, 0 for network failure) and a shared `fetchJson` that uses the server's `reason` on non-2xx and handles unreadable bodies. `src/api/geocoding.ts` has `searchCities` (returns `[]` when `results` is omitted; rejects queries under 2 characters). `src/api/weather.ts` has `fetchForecast` (one call for current, hourly and daily with `timezone=auto` and unit params), column-to-row transformers (null probabilities and UV default to 0) and `validateCoordinates`, which throws before any request. `src/utils/weatherCodes.ts` maps WMO codes to `{ description, icon, group }` with day/night emoji icons and an unknown fallback. `src/store/useAppStore.ts` is a units-only Zustand store. `useCitySearch` is enabled at 2 or more characters with a 1 hour `staleTime`; `useForecast` uses key `['weather', lat, lon, units]` and reads units from the store. `src/test/handlers.ts` has MSW handlers and fixtures for both endpoints. 49 tests pass across 8 files, covering transformers, errors, weather codes and both hooks, including refetch on units change.

- **Hourly Forecast:** Added a horizontally scrolling "Next 24 hours" strip below the current-conditions card on the City page, with no new API code. `sliceHourly` in `src/utils/hourly.ts` floors `current.time` to the hour and takes 24 points by comparing the API's location-local timestamp strings, so midnight and month rollover work and the viewer's timezone never matters; it returns fewer items if the data ends early and none if it is stale. `formatHour` formats the hour with `Intl.DateTimeFormat` in UTC over the local wall-clock value, using the viewer's 12/24-hour default. `isDaytime` derives the day/night icon from that date's sunrise and sunset (sunrise inclusive, sunset exclusive, day if the date is unknown) because hourly data has no day flag. `HourlyList` renders a focusable list (`tabIndex=0`, labelled by its heading) with scroll-snap items showing time, icon, rounded temperature in the active units and precipitation chance, with a visually hidden "N% chance of precipitation" label for screen readers; the first item reads "Now". `HourlyListSkeleton` shows while loading. `City.tsx` renders both from the same `useForecast` data, so there is one request and errors reuse the page's existing `ErrorState` and Retry. Existing City and UnitToggle tests were scoped to the current-conditions card because temperatures now appear in the strip too. 106 tests pass across 16 files, covering slicing (rollover, mid-hour, short, stale, empty), hour formatting in 12 and 24-hour locales, day/night boundaries, the component and the City page (24 items from one request, skeleton). Not checked in a browser; scroll snap is CSS-only and untested in jsdom, and the Now border always uses the day accent colour.

- **What to Wear:** Added a rule-based clothing suggestion card on the City page, with no new API code. `getOutfit` in `src/utils/outfit.ts` is a pure function taking feels-like °C, rain chance, wind km/h, UV index and `isDay`, and returning `{ summary, items, tips }`. Temperature bands are ≤0 (heavy coat, hat, gloves), under 11 (warm jacket), under 18 (sweater), under 25 (light layers) and 25 or more (light clothing); rain chance of 40% or more adds an umbrella or rain jacket, wind of 30 km/h or more adds a windbreaker, and UV of 6 or more adds sunscreen and sunglasses, by day only. `toCelsius` and `toKmh` convert from the user's units first, so unit settings never change the advice. `worstRainChance` takes the maximum chance over the next 6 hours (`RAIN_LOOKAHEAD_HOURS`, chosen because the spec only said "next few hours"). `OutfitCard` (`src/components/outfit/`) shows a headline, the items as violet pills and short tips, and sits between the current-conditions card and the hourly strip; `City.tsx` now computes the hourly slice once and shares it. 144 tests pass, including table-driven boundary tests, imperial-versus-metric equivalence and three component scenarios. Not checked in a browser; UV advice is ignored at night, and the card has no loading skeleton of its own because it renders only once the forecast has loaded.

- **Air Quality:** Added an air quality card to the City page, between the current-conditions and outfit cards. `src/api/airQuality.ts` calls Open-Meteo's air quality endpoint (`air-quality-api.open-meteo.com/v1/air-quality`) for `current=us_aqi,pm2_5,pm10`, validates coordinates first and maps the response to an `AirQuality` type whose readings are all nullable, returning `null` when there is no `current` block. `useAirQuality(lat, lon)` wraps it in TanStack Query under `['air-quality', lat, lon]`. `getAqiCategory` in `src/utils/airQuality.ts` maps US AQI to Good, Moderate, Unhealthy for sensitive groups, Unhealthy, Very unhealthy or Hazardous (breakpoints 50/100/150/200/300), each with a level 0-5 and a short health note. `AirQualityCard` (`src/components/airquality/`) shows the rounded AQI, category, note and PM2.5/PM10 in µg/m³; the level sets a left-border and badge colour via `data-level`, and each level also has its own symbol and the label is always text, so colour is never the only signal. It fetches on its own with a skeleton, an error with Retry, and a "not available for this location" state when the AQI is missing, so a failure here does not touch the rest of the page. The test handlers gained an air quality fixture and URL. 166 tests pass across 25 files: table-driven category boundaries, API transform and request parameters, invalid coordinates making no request, server error as `ApiError`, and card states (data, no data, error then Retry) with MSW. The endpoint was confirmed in the docs but `us_aqi`, `pm2_5` and `pm10` come from memory, so they are only exercised by mocks. Not checked in a browser; the white symbol on the yellow Moderate badge is about 3:1 contrast, the card only mounts after the forecast loads so its skeleton is rarely seen, and European AQI is not offered.
