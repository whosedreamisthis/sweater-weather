- **Project Setup:** Installed TanStack Query, Zustand, React Router, Vitest, Testing Library, jsdom and MSW. `src/api/queryClient.ts` creates the `QueryClient` (5 min `staleTime`, up to 2 retries, never on 4xx via `shouldRetry`) and `App.tsx` wraps the app in `QueryClientProvider`. `src/router.tsx` defines a hash router (GitHub Pages friendly) with a shared `Layout` (header, nav, `<Outlet />`) and placeholder Home, City (`/city/:lat/:lon`), Settings and NotFound pages. Added the `api/`, `hooks/`, `store/`, `components/`, `pages/`, `utils/`, `test/` folders and replaced the Vite starter styles with CSS custom property tokens and a reset in `src/index.css`. Vitest runs in jsdom with globals, loading `src/test/setup.ts` (jest-dom, MSW server with `onUnhandledRequest: 'error'`); `renderWithProviders` gives each test a fresh `QueryClient` with `retry: false`. 8 tests cover `shouldRetry`, the client defaults and routing. The deploy workflow now runs `npm test` before the build. Also added 13 feature specs in `context/features/` and rewrote `coding-standards.md`, `ai-interaction.md` and `README.md` for this stack.

- **Weather API Layer:** Added typed Open-Meteo clients and TanStack Query hooks with no UI. `src/api/types.ts` holds `Units`, `Location`, `CurrentWeather`, `HourlyPoint`, `DailyPoint` and `Forecast`; `Forecast.location` is a `ForecastLocation` (latitude, longitude, timezone) because the forecast endpoint returns no name or id. `src/api/http.ts` provides `ApiError` (numeric `status`, 0 for network failure) and a shared `fetchJson` that uses the server's `reason` on non-2xx and handles unreadable bodies. `src/api/geocoding.ts` has `searchCities` (returns `[]` when `results` is omitted; rejects queries under 2 characters). `src/api/weather.ts` has `fetchForecast` (one call for current, hourly and daily with `timezone=auto` and unit params), column-to-row transformers (null probabilities and UV default to 0) and `validateCoordinates`, which throws before any request. `src/utils/weatherCodes.ts` maps WMO codes to `{ description, icon, group }` with day/night emoji icons and an unknown fallback. `src/store/useAppStore.ts` is a units-only Zustand store. `useCitySearch` is enabled at 2 or more characters with a 1 hour `staleTime`; `useForecast` uses key `['weather', lat, lon, units]` and reads units from the store. `src/test/handlers.ts` has MSW handlers and fixtures for both endpoints. 49 tests pass across 8 files, covering transformers, errors, weather codes and both hooks, including refetch on units change.

- **City Search:** Added the autocomplete `SearchBox` (`src/components/SearchBox.tsx`) with no new API code; it uses `useCitySearch` and a new `useDebouncedValue` hook (300 ms). The input is a `role="combobox"` with a listbox of up to 5 results (name plus region and country), a loading state (also shown while typing ahead of the debounce), an error state with Retry, a "No cities found" empty state, and nothing for queries under 2 characters. Selecting a result (click or Enter) navigates to `/city/:lat/:lon?name=<encoded name>`, fills the input with the name and closes the list. Keyboard: ArrowUp/ArrowDown cycle with wrap-around and set `aria-activedescendant`/`aria-selected`; Enter selects only when an option is active; Escape closes and keeps the text; typing or focusing reopens. A polite `role="status"` live region announces the result count or "No cities found". `aria-controls` is set only while the list is open. A clear button (shown when there is text) empties and refocuses the input, and a document `pointerdown` listener closes the list on outside click. Placement: `Layout` renders the search in the header on every route except `/`, where `Home` renders it in the page body, so only one is ever on screen. The header wraps mobile-first, with the search on its own full-width row below 640px. 64 tests pass across 10 files, covering the hook (fake timers), the component (MSW results, 5-result cap, empty, error with retry, selection, live region, keyboard, Escape, clear, outside click) and header/Home placement. Not checked in a browser at 375px, and the loading state is not announced in the live region.

- **Current Conditions:** Replaced the placeholder City page with the live hero card. `src/pages/City.tsx` reads `lat`, `lon` and `?name=` (falling back to the coordinates as the heading), calls `useForecast`, sets `document.title` to the city name and chooses between an error, the skeleton or the card. A 400 `ApiError` (invalid or out-of-range coordinates) shows a friendly "Location not found" message with no Retry; any other error shows a message with a Retry button that calls `refetch`. `src/components/current/CurrentWeather.tsx` is presentational: name, large temperature, feels-like, icon and description from `describeWeatherCode`, and a `<dl>` of humidity, wind with compass direction, pressure (hPa), UV index and visibility (km). `data-time` (day/night) and `data-group` (weather group) drive the `--card-accent` border colour from new `--accent-*` tokens in `src/index.css`. `CurrentWeatherSkeleton` reuses the card layout and respects `prefers-reduced-motion`; `ErrorState` is a generic `role="alert"` box. "Updated N min ago" comes from `dataUpdatedAt` and the new `useNow` hook (30 s tick), with "Refreshing…" while `isFetching`. The API layer now requests `uv_index` and `visibility`: `uvIndex` defaults to 0 when missing, while `visibility` (metres) stays `null` and displays as "—". `src/utils/format.ts` holds `compassDirection`, `formatVisibility`, `minutesAgo` and `formatUpdated`. `index.html` gained a real title, meta description, Open Graph/Twitter tags, `theme-color` and a `<noscript>` message. 82 tests pass across 12 files, including `City.test.tsx` (success, skeleton, error then Retry, invalid coordinates) and table-driven `format.test.ts`. Not checked in a browser; visibility is always km regardless of the units setting (left for the units-toggle feature), and `ErrorState` should move to `components/` once a second page uses it.

- **Units Toggle:** Expanded `src/store/useAppStore.ts` with Zustand `persist` (localStorage key `sweater-weather`, only `units` saved) and a `setUnits` action that merges partial updates. Defaults come from `navigator.language` via `defaultUnitsFor`: `en-US` gets °F, mph and inches, everything else metric (`DEFAULT_UNITS` stays the metric constant). `safeStorage` wraps getItem/setItem/removeItem in try/catch so the app works when storage is blocked. The forecast request and query key already carried units, so switching refetches in the new units, cached per unit set. `UnitToggle` is a small square header button (aria-label "Switch to Fahrenheit/Celsius"); the Settings page has temperature, wind and precipitation groups built as segmented controls over native radios (visually hidden, so keyboard and screen readers still work). Also added a cloud-and-sun `Logo` beside the header title, the same mark as `public/favicon.svg`, and centered the city card. 90 tests pass across 14 files, including store actions, persistence and rehydrate, safeStorage failures, and MSW per-unit-param toggling tests. Tests stub an in-memory localStorage because Node's global one shadows jsdom's. Not checked in a browser; visibility and pressure stay km and hPa regardless of units, and only temperature and wind are displayed so far (precipitation is requested but not shown yet).
